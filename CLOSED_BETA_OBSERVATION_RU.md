# Closed Beta Observation & Feedback Loop

Статус: реализован технический контур наблюдения поверх существующей privacy-safe telemetry.

## Что добавлено

- Компактный Beta Health на первом уровне админки.
- Beta Dashboard по событиям Mini App: запуск, поиск, успешный/пустой поиск, матч, AI start/complete, LIVE, история, профиль.
- action_error показывается только агрегированно по категориям; тексты ошибок и пользовательские запросы не выводятся.
- Время ответа для поиска, матча, AI и LIVE. Median показывается при n >= 3, P90 — при n >= 10.
- Кнопка «Сообщить о проблеме» для beta-пользователя с явным перечнем передаваемых данных.
- Feedback хранится без Telegram ID в beta-записи; Telegram-аутентификация используется только для проверки сессии.
- Классификация проблем BLOCKER / MAJOR / MINOR.
- Единичный субъективный feedback не становится активной проблемой без повторения или корреляции с telemetry.
- Технические разделы Runtime, Provider, Diagnostics, Release и Model Quality сохранены и перенесены на второй уровень.

## Источники данных

Новая таблица Supabase не требуется. Dashboard агрегирует существующие growth_events и ops_events. Идентификаторы могут использоваться только сервером для подсчёта уникальных пользователей и никогда не возвращаются из Beta Dashboard.

## Правило подтверждения проблемы

- BLOCKER: повторённый blocker feedback либо подтверждённый высокий процент отказов основной функции.
- MAJOR: повторённая telemetry-ошибка, повторённый major feedback или корреляция feedback + telemetry.
- MINOR: повторённый minor feedback без признаков отказа основной функции.
- Один feedback без подтверждения остаётся needs_more_evidence.

## Категории отчёта

Поиск; матчи; AI; LIVE; UX; источники данных; производительность.

Для каждой категории API формирует частоту, влияние на пользователя, evidence и рекомендуемое направление исправления. Исправление продукта не выполняется автоматически.

## Provider decision guard

Новый или платный football provider не предлагается только из-за красивых процентов Dashboard. Основание появляется только после накопления устойчивых provider/rate-limit/отсутствующих-data сигналов на реальных beta-пользователях.

## Финальный beta-отчёт

Beta Dashboard уже рассчитывает основу будущего отчёта: количество beta-пользователей, core journey completion, основной отказ, реально используемые и малоиспользуемые функции, сигналы отсутствующих данных, provider evidence и readiness к расширению beta.

Фактический итоговый отчёт формируется после накопления реальных closed-beta данных; до этого любые выводы о provider или расширении аудитории считаются предварительными.


## Closed-beta cohort boundary

Dashboard учитывает только события с серверной меткой `closed_beta_v1`. События, записанные до включения этого этапа, не входят в beta-метрики даже при выборе окна 7/14/30 дней. Cohort ставится сервером на growth/ops telemetry и beta feedback, поэтому пользователь не может подменить его из клиента.
