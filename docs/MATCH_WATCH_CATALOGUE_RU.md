# «Где смотреть»: каталог и плеер

## Текущее состояние

YouTube Data API v3 принимает существующий GitHub secret `YOUTUBE_DATA_API_KEY`: защищённый запуск [39956319359](https://github.com/TRAP44/football-analytics-cloudflare/actions/runs/39956319359) подтвердил канал FIFA. Пять найденных upcoming-видео оказались показами записей прошлых матчей. Подтверждённых текущих LIVE-источников в этом запуске нет. Это не ошибка ключа.

В `src/match-watch-approvals.json` пока пустой каталог. Поэтому пользователь не увидит пустую панель или неработающую кнопку. Код просмотра готовится к выпуску отдельно от подтверждения конкретных трансляций; пустой каталог и браузерный тест не доказывают доступность видео в Telegram/России. Исследование источников и ограничения: [MATCH_WATCH_SOURCES_RU.md](MATCH_WATCH_SOURCES_RU.md).

## Как работает просмотр

У подтверждённого матча появляется компактный блок «Где смотреть». Сначала человек выбирает страну. Язык Telegram и IP не заменяют этот выбор. Варианты имеют отдельные типы: трансляция, полная запись, обзор; указаны бесплатность, подписка, отдельная покупка или условия источника.

Для разрешённого YouTube embed доступны кнопка «Смотреть в приложении» и официальная ссылка. Если встраивание запрещено, остаётся переход к источнику. Сторонний плеер и SDK не загружаются до нажатия; autoplay выключен. Ограничения аккаунта, региона, подписки и правообладателя применяет сам источник. Никакого извлечения потоков, обхода DRM, ретрансляции или удаления рекламы нет.

В карточке бота «Где смотреть» ведёт к тому же матчу в Mini App с открытым блоком выбора страны. Кнопка появляется только при действующем подтверждённом варианте хотя бы для одной страны. Бот не обещает, что этот вариант доступен конкретному человеку до выбора страны.

LIVE-перерисовка не переносит iframe: панель находится вне заменяемого `#analysis`. Смена страны, матча и уход с экрана закрывают воспроизведение. Ошибка/удаление/запрет плеера оставляют официальную ссылку; истёкшие сведения удаляются и перечитываются.

## Добавление реального источника

Manifest хранится под `src/`, чтобы его изменения и отзыв попадали в обязательный production artifact diff. Каталог редактируется через обычный проверенный PR, без нового ключа и без публичного API публикации. Одна запись содержит:

| Поле | Проверка |
|---|---|
| `match` | Точный `fixtureId`, `home.id`, `away.id`, `leagueId`, `season`, `date` из канонического центра матча |
| `provider`, `eventUrl` | Только разрешённый официальный HTTPS URL конкретного события, без редиректоров и произвольного iframe |
| `publisher`, `videoId` | Для YouTube — `fifa` и точный ID видео принадлежащего проверенному официальному каналу |
| `kind` | `live`, `replay` или `highlights`; архивная премьера не является сегодняшним футбольным LIVE |
| `access` | `free`, `subscription`, `ppv` или `unknown` — по фактическим условиям источника |
| `countries` | Явно проверенные ISO 3166-1 alpha-2 страны; не выводить права из названия канала или отсутствия regionRestriction |
| `confirmed`, `confirmedAt`, `validUntil` | Результат ручной проверки; срок одобрения не более семи дней |

Перед добавлением в описании PR нужны ссылки на первоисточник и проверка команд, турнира, категории/возраста, даты, типа видео, территории и условий доступа. Текущее совпадение названия/времени из исследовательского скрипта само по себе недостаточно. Встроенный YouTube допускается только со своего официального канала и с разрешённым embed. Официальные DAZN/Okko URL проходят отдельный узкий allowlist и открываются внешне; их наличие в коде не означает заключённую интеграцию или подтверждённое покрытие. Не генерировать URL из fixtureId.

Новый официальный YouTube publisher требует отдельного подтверждения ссылки с сайта правообладателя, проверки channel ID и изменения закреплённого реестра. Пользовательские ссылки и автоматические результаты поиска не попадают в каталог.

После merge/deploy:

1. Убедиться, что этот матч есть в свежем общем кеше Match Center. Проверка не вызывает футбольный API за каждого зрителя; кеш создаёт обычное открытие матча.
2. Запустить GitHub Actions **Refresh Match Watch** на `main` либо дождаться расписания раз в десять минут. При пустом каталоге нет ни одного обращения к Google/Supabase.
3. Проверить агрегированный artifact `match-watch-refresh.json`: публикация >0, нет `errorCode`. Пропуск из-за отсутствия свежего Match Center не равен подтверждённой публикации.
4. Проверить конкретный матч с выбранной страной в настоящем Telegram: воспроизведение/звук/fullscreen, закрытие, официальный переход. Факт `embeddable=true` этого не доказывает.

## Кеш, отзыв и отказ источника

Защищённый main-only workflow читает тот же текущий manifest, не принимает пользовательские URL/SQL/модели. Для всех одобренных YouTube-видео используется один `videos.list` без поиска/пагинации. Проверяются владелец канала, public/age/region metadata, текущий тип видео и время; отсекаются несовпадения. Региональная метаинформация дополнительно сужает вручную проверенный список стран.

Снимок хранится в существующем `analysis_cache` в namespace `match-watch:FIXTURE:v1`, максимум на30минут и не дольше `validUntil`. Запись через имеющийся `write_analysis_cache_versioned` не перетирает более свежую. Неизвестный результат POST не повторяется автоматически. При удалённом/закрытом видео для этой fixture записывается пустой каталог. Ошибка обновления не продлевает TTL; задержка GitHub может временно скрыть просмотр.

Каждый запрос API и кнопка бота сверяют кеш с текущим **выпущенным manifest**. После выпуска удаления/изменения approval старый кеш не обходит отзыв; не нужно ждать его TTL. Уже открытый клиент обновляет свои сведения по истечении полученного срока. Критическое выключение всех новых выдач: `MATCH_WATCH_ENABLED=false` в Worker; оно не может дистанционно остановить уже открытый внешний сайт.

Публичный `GET /api/match-watch` требует прежнюю подписанную Telegram-сессию. Только чтение кеша, никакого YouTube/Football/AI запроса из пользовательского пути. Нет записей для fixture — ответ без чтения DB. Дополнительное ожидание кеша ограничено500мс в боте и1500мс в API; поздний результат не добавляет кнопку к уже отправленному сообщению. Ключ YouTube остаётся в GitHub, не переносится в браузер или Worker. Схема Supabase, платежи и AI-квоты не менялись.

CSP разрешает только официальный YouTube iframe и SDK; admin/status/privacy/terms дополнительно сохраняют прежнюю строгую политику. Referrer-Policy остаётся `no-referrer` глобально; только iframe/SDK получают `strict-origin-when-cross-origin`, необходимый для идентификации встроенного плеера.

## Проверки

`test/match-watch.test.js` проверяет идентичность матча, отзыв manifest/территории, TTL, смену типа видео, официальные URL, издателя/регионы, бюджеты и неизвестный результат записи, auth/GET/route/cache-only. Проверка кнопки — в `test/telegram-bot-ui-runtime-boundaries.test.js`.

`node scripts/match-watch-browser-smoke.js` использует настоящий Chromium, HTTP и API с синтетическим одобренным матчем и заглушкой YouTube SDK. Проверяет явную страну, отсутствие autoplay/медиа до клика, fallback при запрете встраивания, немедленное закрытие при смене страны/навигации и ширины320/390/900. Это не проверка реального Telegram или реального видео. Он включён в Quality рядом с существующими browser smoke.
