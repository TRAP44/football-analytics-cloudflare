## Как работает просмотр

У подтверждённого матча появляется компактный блок «Где смотреть». Сначала человек выбирает страну. Язык Telegram и IP не заменяют этот выбор. Варианты имеют отдельные типы: трансляция, полная запись, обзор; указаны бесплатность, подписка, отдельная покупка или условия источника.

Для разрешённого YouTube embed доступны кнопка «Смотреть в приложении» и официальная ссылка. Если встраивание запрещено, остаётся переход к источнику. Сторонний плеер и SDK не загружаются до нажатия; autoplay выключен. Ограничения аккаунта, региона, подписки и правообладателя применяет сам источник. Никакого извлечения потоков, обхода DRM, ретрансляции или удаления рекламы нет.

В карточке бота «Где смотреть» ведёт к тому же матчу в Mini App с открытым блоком выбора страны. Кнопка появляется только при действующем подтверждённом варианте хотя бы для одной страны. Бот не обещает, что этот вариант доступен конкретному человеку до выбора страны.

LIVE-перерисовка не переносит iframe: панель находится вне заменяемого `#analysis`. Смена страны, матча и уход с экрана закрывают воспроизведение. Ошибка/удаление/запрет плеера оставляют официальную ссылку; истёкшие сведения удаляются и перечитываются.

## Автоматическое наполнение

`src/match-watch-policy.js` закрепляет официальный канал, турнир, наблюдавшийся формат полного LIVE, страны и точные исключения имён команд по provider ID. Сейчас автоматический источник — **J.LEAGUE International, J1 League (98), RU/KZ/BY**. FIFA и SPL не включены в автоматическую публикацию: у FIFA найдены архивы, для SPL ещё нет проверенного формата конкретного эфира. Это не обещание покрытия всех турниров.

Фоновый Refresh сам находит LIVE/upcoming видео: два ограниченных поиска YouTube не чаще одного раза за два часа, без пагинации и повторов. При одном источнике это максимум 24 поисковых запроса за 24 часа непрерывной работы; ручной исследовательский workflow имеет отдельный расход. Маркер попытки сохраняется **до** запросов, включая неудачный поиск. Общая concurrency-группа ручного и автоматического workflow исключает параллельные поиски. Ошибка подтверждения записи маркера останавливает поиск. Найденные ID сохраняются; один batched `videos.list` проверяет свежую доступность на каждом обычном пятиминутном тике. Точные интервалы зависят от очереди GitHub.

Матчи берутся только из существующего свежего общего provider day-cache и независимых Match Center, с полными fixture/team/league/season/date. Допускаются сохранённые канонические свидетельства не старше 48 часов, в том числе уже проверенные вручную два первых матча. Новых Football запросов и ключей нет. Если канонических сведений о матче пока нет, эфир ждёт их появления в обычном кеше приложения; название видео не создаёт фиктивный матч.

Автопривязка требует полного наблюдавшегося формата названия, точного порядка команд, канонического турнира, единственного совпадения и начала эфира от 15 минут до матча до 5 минут после. Только предстоящие/идущие матчи в пределах 48 часов. Неизвестные форматы, неоднозначность, переносы, отмены, архивы, возрастные ограничения, приватные и удалённые видео исключаются. Территории дополнительно сужаются свежими region restrictions YouTube. Запрет embed оставляет официальную ссылку.

Автоматические записи имеют approval v2 с ID/ревизией политики. Production runtime повторно сверяет её с текущим выпущенным кодом: удаление политики, смена канала/ревизии/стран отзывает старый кеш. Публичный API по-прежнему требует подтверждённую Telegram-сессию и независимый свежий центр **того же** матча. Старые привязки очищаются при следующей проверке; при недоступности фонового процесса действует общий TTL 30 минут. Бот и Mini App не обращаются к YouTube и не запускают поиск при каждом посетителе.

Для новых матчей этого источника PR больше не нужен. Новый официальный канал или новый формат добавляется отдельным проверенным изменением политики. Воспроизведение в настоящем Telegram проверяется отдельно и не выводится из успешного поиска/metadata или тестового iframe.

## Добавление реального источника

Manifest хранится под `src/`, чтобы его изменения и отзыв попадали в обязательный production artifact diff. Ручное исключение редактируется через обычный проверенный PR, без нового ключа и без публичного API публикации. Автоматические LIVE используют политику выше. Одна запись содержит:

| Поле | Проверка |
|---|---|
| `match` | Точный `fixtureId`, `home.id`, `away.id`, `leagueId`, `season`, `date` из канонического центра матча |
| `provider`, `eventUrl` | Только разрешённый официальный HTTPS URL конкретного события, без редиректоров и произвольного iframe |
| `publisher`, `videoId` | Для YouTube — `fifa` и точный ID видео принадлежащего проверенному официальному каналу |
| `kind` | `live`, `replay` или `highlights`; архивная премьера не является сегодняшним футбольным LIVE |
| `access` | `free`, `subscription`, `ppv` или `unknown` — по фактическим условиям источника |
| `countries` | Явно проверенные ISO 3166-1 alpha-2 страны; не выводить права из названия канала или отсутствия regionRestriction |
| `confirmed`, `confirmedAt`, `validUntil` | Результат ручной проверки; срок одобрения не более семи дней |

Перед добавлением в описании PR нужны ссылки на первоисточник и проверка команд, турнира, категории/возраста, даты, типа видео, территории и условий доступа. Текущее совпадение названия/времени из исследовательского скрипта само по себе недостаточно. Встроенный YouTube допускается только со своего официального канала и с разрешённым embed. Официальные DAZN/Okko URL проходят отдельный узкий allowlist и открываются внешне; их наличие в коде не означает заключённую интеграцию или подтверждённое покрытие. Не генерировать URL из fixtureId.

Новый официальный YouTube publisher требует отдельного подтверждения ссылки с сайта правообладателя, проверки channel ID и изменения закреплённого реестра. Пользовательские ссылки и автоматические результаты поиска не попадают в каталог.

После merge/deploy:

1. Убедиться, что этот матч есть в свежем общем кеше Match Center. Для подготовки до первого посещения разрешено приложить к одобрению `fixtureEvidence`: `provider: "api-football"`, точные `fixtureIdentity` и `observedAt` из защищённой проверки не старше48ч. Это позволяет подготовить каталог, но не создаёт фиктивный Match Center: публичная выдача всё равно требует независимый свежий центр с той же идентичностью. Конфликт с существующим центром отклоняется.
2. Запустить GitHub Actions **Refresh Match Watch** на `main` либо дождаться следующего пятиминутного **Background Jobs → watch**. При пустом каталоге нет ни одного обращения к Google/Supabase.
3. Проверить агрегированный artifact `match-watch-refresh.json`: публикация >0, нет `errorCode`. Пропуск из-за отсутствия свежего Match Center не равен подтверждённой публикации.
4. Проверить конкретный матч с выбранной страной в настоящем Telegram: воспроизведение/звук/fullscreen, закрытие, официальный переход. Факт `embeddable=true` этого не доказывает.

## Кеш, отзыв и отказ источника

Защищённая задача **Background Jobs → watch**, запускаемая существующим Cloudflare dispatch каждые пять минут, читает тот же текущий manifest, не принимает пользовательские URL/SQL/модели. Для всех одобренных YouTube-видео используется один `videos.list` без поиска/пагинации. Проверяются владелец канала, public/age/region metadata, текущий тип видео и время; отсекаются несовпадения. Региональная метаинформация дополнительно сужает вручную проверенный список стран.

Снимок хранится в существующем `analysis_cache` в namespace `match-watch:FIXTURE:v1`, максимум на30минут и не дольше `validUntil`. Запись через имеющийся `write_analysis_cache_versioned` не перетирает более свежую. Неизвестный результат POST не повторяется автоматически. При удалённом/закрытом видео для этой fixture записывается пустой каталог. Ошибка обновления не продлевает TTL; задержка GitHub может временно скрыть просмотр.

Каждый запрос API и кнопка бота сверяют кеш с текущим **выпущенным manifest**. После выпуска удаления/изменения approval старый кеш не обходит отзыв; не нужно ждать его TTL. Уже открытый клиент обновляет свои сведения по истечении полученного срока. Критическое выключение всех новых выдач: `MATCH_WATCH_ENABLED=false` в Worker; оно не может дистанционно остановить уже открытый внешний сайт.

Публичный `GET /api/match-watch` требует прежнюю подписанную Telegram-сессию. Только чтение кеша, никакого YouTube/Football/AI запроса из пользовательского пути. Нет записей для fixture — ответ без чтения DB. Дополнительное ожидание кеша ограничено500мс в боте и1500мс в API; поздний результат не добавляет кнопку к уже отправленному сообщению. Ключ YouTube остаётся в GitHub, не переносится в браузер или Worker. Схема Supabase, платежи и AI-квоты не менялись.

CSP разрешает только официальный YouTube iframe и SDK; admin/status/privacy/terms дополнительно сохраняют прежнюю строгую политику. Referrer-Policy остаётся `no-referrer` глобально; только iframe/SDK получают `strict-origin-when-cross-origin`, необходимый для идентификации встроенного плеера.

## Подключение первого источника

Официальный сайт [Singapore Premier League](https://spl.sg/) сам ссылается на `@sgpremierleague`; ID канала `UCiJTKr-wja_JVM2dVTYCELA` закреплён в коде. Анонс [5-го тура](https://spl.sg/news/spl-2026-27-matchweek-5-top-three-look-to-extend-unbeaten-starts/) от23октября указывает Young Lions — Balestier Khalsa, 24октября2026 19:30SGT /14:30МСК, YouTube или meWATCH. Это кандидат, ещё не одобренное видео или подтверждение прав для России.

`watch_fixture_id` — необязательный точный положительный ID, максимум один запрос `/fixtures?id=…`. Используется существующий relay из доверенного `wrangler.jsonc`, без workflow-параметра URL и без прямого fallback. До запроса проверяются общие quota/cooldown и делается один `claim_provider_request` в том же production minute bucket с консервативным пределом4. Недоступность/неоднозначный результат проверки останавливают provider GET, повторов нет. Это единственная операционная запись лимита: пользовательские и футбольные данные не изменяются. Ключи Google, футбольного API и Supabase остаются раздельными, в артефакте только публичные данные матча и фиксированные коды ошибок.

Google-проверка использует максимум4 GET (из них2 поиска) только выбранного официального канала; точный channel ID и handle проверяются перед поиском. Она не одобряет видео автоматически и не доказывает playback. Полный тип/территория/турнир проверяются перед отдельным добавлением approval.

### Надёжные часы обновления

Отдельный GitHub cron оказался ненадёжным: workflow был active более часа, но запусков по schedule не было. В проекте уже есть рабочие часы — Cloudflare вызывает **Background Jobs** через workflow_dispatch каждые пять минут. Обновление просмотра выполняется отдельной параллельной задачей `watch` этого workflow. У неё собственные main-only/environment ограничения, только Google/Supabase keys, deadline3мин и общий с ручным Refresh Match Watch concurrency key. Telegram и Football keys туда не передаются; leases и порядок задач напоминаний не меняются. Сбой `watch` виден в отдельной задаче и её JSON artifact, но не останавливает независимую задачу отправки уведомлений. В recovery preview/apply просмотр не запускается. Отдельный Refresh Match Watch оставлен ручным, повторного schedule нет.
