# Массовый первый вход: пакетная синхронизация профилей

15.10.2026. Продолжение #902. Цель — снизить очередь при первом открытии ленты, где каждый новый пользователь требовал отдельный POST users.

Профили группируются внутри одного runtime по точной паре Supabase URL/key: до 100 пользователей или 2 мс. Каждый запрос ждёт подтверждения записи; только затем обновляется прежний userSyncAt (10 минут). Telegram HMAC/freshness, singleflight, чтение прав/квот сохранены. Поля записи прежние: telegram_id, username, first_name, last_name, photo_url, updated_at. Подписка не входит в payload.

URL/key фиксируются при постановке в очередь. Неизвестные identity и повторяющиеся ID не объединяются. Строки сортируются по telegram_id для стабильного порядка блокировок. При ошибке пакета каждый профиль повторяется отдельно: один невалидный профиль не блокирует остальные записи, неуспех не отмечается как успешная синхронизация. В одиночном запросе при ошибке дополнительных retries нет. При малом трафике добавляется окно 2 мс плюс планирование event loop. При полном отказе БД возможен один неудачный batch перед индивидуальными попытками.
