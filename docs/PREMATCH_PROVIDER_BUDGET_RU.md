# Фоновые прогнозы: замер и резерв API-Football

Первый этап усиления существующей задачи 2 (#831): реальные запросы ограничены отдельно от количества разборов. Вид карточек и скрытые по решению Сергея полоски вероятностей не меняются.

## Воспроизводимый изолированный замер

Node 22: `node scripts/measure-prematch-provider-cost.js`.

Скрипт выполняет настоящий конвейер анализа из композиции Worker. Вместо API-Football и Supabase — локальные подставные ответы; fetch запрещает любые хосты кроме двух тестовых. Ключи из среды не используются. Проверяются полноценный HTTP 200 и повторный ответ из кеша. Данные матчей демонстрационные, не production.

| Сценарий | Запросы API-Football на матч |
| --- | ---: |
| Пустой кеш, за 120 минут до старта | 9 |
| Пустой кеш, за 60 минут до старта | 10 |
| Повторный разбор из кеша | 0 |

Девять запросов: fixture, injuries, predictions, odds, headtohead, форма двух команд, статистика сезона двух команд. В окне составов добавляется lineups. Сценарий использует PRO, обычный взрослый турнир, без судьи и без объявленного состава; расширение данных игроков/судьи и retries могут изменить расход. Это замер конкретных сценариев, **не универсальный максимум**. Все запросы идут через настроенный `API_FOOTBALL_BASE_URL`; тест использует подставной ретранслятор с тем же форматом URL.

Запросы списка матчей при полностью пустом кеше — дополнительно до двух `/fixtures?date`, на запуск, а не на каждый разбор. Они тоже попадают в новый бюджет. `/status` не расходует дневную квоту источника и исключён из него. Supabase-запросы не считаются запросами API-Football.

## Защита живых пользователей

- Потолок сетевых запросов фона — 25% подтверждённого лимита, максимум **1875 из 7500**. Для меньшего тарифа потолок тоже уменьшается. Ограничение числа разборов (сейчас 60/сутки) действует дополнительно.
- Используется атомарный `claim_provider_request` и существующие 24 часовые корзины `prematch-provider-requests:hHH`. Каждый сетевой запрос, включая retry, допускается отдельно. Ошибка чтения/RPC блокирует фон.
- Фон останавливается, если подтверждённый общий расход достиг 50%. Это консервативнее выделения только пользовательского расхода: учитывается и уже потраченный фон.
- Без дневного остатка за текущие сутки или со снимком старше 30 минут фон не начинает расчёт; перед запуском спрашивает бесплатный `/status`, если нужно. Во время расчёта проверка повторяется перед транспортом.
- Функция допуска передаётся только в конфигурацию данного фонового задания. Пользовательская кнопка «Разобрать» не использует фоновый потолок; общие защитные лимиты источника по-прежнему действуют.

Граница: решение принимается по последнему доступному снимку квоты, а не по мгновенной квоте внешнего сервиса. Суточный потолок самого фона атомарен; параллельный внешний расход становится виден при обновлении снимка.

## Выключить без деплоя

GitHub репозитория → Settings → Environments → `background-jobs` → Environment variables → `PREMATCH_PREDICTIONS_ENABLED=false`.

Со следующего запуска GitHub-фона расчёт отключён без изменения Worker. Пустая/отсутствующая переменная оставляет значение wrangler; `true` включает, любое непустое некорректное значение безопасно отключает. Уже выполняющийся запуск не прерывается. Изменение здесь действует на GitHub-фон (текущий `BACKGROUND_JOBS_EXECUTOR=github`), а не на настройки Worker в Cloudflare.

## Журнал и следующие этапы

Одна запись `prematch_predictions_run` в `ops_events` для каждого действительного запуска, включая пропуск из-за бюджета/источника. Поля: посчитано, уже кешировано, пропущено, ошибки, причина остановки, `providerRequestsReserved` и `providerRequestLimit`. Резервирование консервативно: не возвращается при сетевой ошибке. Тики вне интервала/отключённая задача не создают записи.

Далее отдельными PR: наблюдаемые команды вместе с избранными; второй расчёт по факту объявленного состава примерно за час до матча с сохранением неизменного первого прогноза для оценки модели; единая отметка «рассчитано в ЧЧ:ММ» в штабе и допустимых карточках. Повторный расчёт каждые пять минут не добавляется.
