# Расширенный просмотр — 27 октября 2026

Сергей попросил существенно больше матчей, а не увеличение одной цифры. Фактические первичные источники: [evidence](research/WATCH_MULTILEAGUE_EVIDENCE_2026-10-27.json). В существующем main-only observer проверены последние публикации семи каналов существующим ключом и семь полных дат API-Football. Никаких писем, договоров, платежей или новых аккаунтов не создавалось.

Для каждой страны остаются только разрешённые свежими YouTube metadata варианты. Например, Wellington—Central Coast полная запись не разрешена RU, но обзор разрешён; для KZ есть запись. Sydney—Adelaide и Melbourne Victory—Melbourne City имеют public/embed/RU metadata. Это наблюдение метаданных и источника, не физическая проверка Telegram playback. Общее количество записей не выдаётся за количество записей в России.

Привязка использует независимый provider fixtureId, команды, лигу/категорию, дату/время и сезон; далее конкретный формат подтверждает тур и/или счёт/явную дату в описании. Для SerieA проверяется независимая первая строка: обнаруженное Atalanta—Frosinone видео с Inter—Fiorentina в описании отвергается. Никаких fuzzy/substring матчей заголовков, перехода женщин в мужскую лигу или замены источника общим каналом. Нормализуются только регистр/акценты/знаки, явные club designators и отдельно закреплённые provider-ID rebrands. Сингапурская Premier League явно подписана страной.

## Автоматическое наполнение и бюджет

Пять каналов/шесть политик; общий A-Leagues channel читается один раз. Новые uploads проверяются каждые5мин дешёвым playlistItems, по50публикаций; J.LEAGUE сохраняет прежние2ч. LIVE/upcoming search J.LEAGUE2ч/A-Leagues6ч. Отказы одного feed не уничтожают результаты другого. В durable state попытка записывается до расходования квоты, неизвестная запись не повторяется. Атомарный DB rate bucket допускает один automatic refresh на300секунд независимо от дублирующих CF/manual/backup clock запусков; rejected claim не вызывает Google/provider/cache writes. Discoveryv2 мигрирует прежние bindings изv1, оставляя его для rollback.

Верхние границы:330feedIDs+200boundIDs+20manual=550, batches по50, максимум20Google calls/run;100матчей, максимум одна полная запись/эфир и один обзор на матч. При нескольких версиях предпочитается подходящая RU, разрешённая к embed; все страны выбранного видео всё равно проверяются. При заданных интервалах худший расчёт Google-квоты — около7532units/day при стандартных10k; это расчёт границ, не измерение аккаунта/гарантия доступной квоты. Добавление шестого канала требует пересчёта bounds и квоты.

Канонические снимки получают максимум два UTC-дня за запуск, максимум16попыток в сутки. Действуют прежние globalminute4, cooldown и FREEreserve20. До вызова записывается attempt marker, включая суточный расход. Один dayGET до5000publicfixtures/8MB заменяет множество запросов по fixtureId; сохраняются только watchedleagues до200строк. Исторические завершённые снимки не опрашиваются заново каждые5мин. Новый завершённый эфир/обзор может вызвать ограниченную15минутами сверку статуса; FT подтверждает только новый ответ футбольного провайдера. Metadata видео не превращают спортивный статус в FT. У зрителей нет новых вызовов провайдеров.

## Каталог и скорость

Расширенный список: `list=1&limit=100`. Он использует отдельный cachev2 до100матчей; старый v1 сохраняет до20 исходных совместимых записей для rollback. Новый клиент рисует20карточек, затем показывает ещё20 по нажатию без API; фильтры «Все», «LIVE», «Полные матчи», «Обзоры» также локальные, с честными счётчиками выбранной страны. Результаты матчей/видеоссылки не раскрываются в списке.

После Telegram auth и featureflag общий публичный snapshot объединяется в пределах одного worker instance на3секунды по монотонным часам. Индивидуальная авторизация, текущие политики/регион/TTL проверяются для каждого запроса. Персональные данные, сессии и API отдельного матча не кешируются этим механизмом. Обычный legacy-list сохраняет сильное чтение. У нового списка первое чтение сильное, cache fallback укладывается в прежние1500мс; просроченный ответ не запускает позднее чтение и не заполняет кеш. Замена содержимого в БД может отражаться в расширенном списке с задержкой до3с; политика/истечение действуют сразу при валидации.

Полные исходные metadata проверяются перед публикацией. Затем из catalogue удаляются дубли match/fixtureEvidence и рекламный текст описаний; сохраняется необходимое независимой проверке доказательство. Менее тяжёлый snapshot и объединение одновременных чтений снижают нагрузку на БД. Локальная проверка50пользователей и100карточек не выдаётся за замер production latency/CloudflareCPU.
