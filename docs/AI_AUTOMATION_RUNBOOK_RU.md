# MatchRadar: безопасная автоматизация Claude + Codex

Статус: **поэтапная интеграция; правила main активны; Codex Cloud Code Review ещё должен быть подключён владельцем**.
Целевой репозиторий: `TRAP44/football-analytics-cloudflare`; основная ветка: `main`.

## Цель
Максимально автоматизировать разработку Telegram Mini App **MatchRadar**, сохранив контроль владельца над релизом. Не заменять действующие Cloudflare Workers, Supabase, API-Football, GitHub Actions Quality и Deploy Production.

## Процесс
1. Владелец создаёт или утверждает GitHub Issue с описанием результата и проверяемыми критериями.
2. Оркестратор назначает ограниченную задачу Claude. Claude создаёт ветку `ai/claude/<issue>-<slug>`, тестирует изменение и открывает **draft PR**.
3. GitHub запускает уже существующие проверки Quality, CodeQL и специализированные security checks по их условиям.
4. Codex Cloud Code Review (через ChatGPT Plus) независимо анализирует фактический diff и публикует ревью в PR без GitHub Actions API-ключа. Ревью не заменяет тесты, обязательные approvals и решение владельца.
5. Claude исправляет обоснованные замечания в своей ветке и снова проходит проверки. Устанавливается ограничение на циклы исправлений, расходы и время исполнения.
6. Владелец изучает diff, критические замечания, фактические результаты обязательных проверок и вручную утверждает merge.
7. Только действующий доверенный `Deploy Production` отвечает за production. AI-агенты не вызывают его напрямую.

## Блокирующая предпосылка: защита main
Первоначально 10.10.2026 ветка была без защиты; после ручной настройки владельцем GitHub подтвердил активный `MatchRadar Main Protection` ruleset для `main` с запретом удаления и force-push, требованием PR и без bypass. **Обязательные status checks и человеческое approval пока НЕ установлены** — они остаются отдельными задачами.

Откройте `Settings > Rules > Rulesets > New branch ruleset` для целевой ветки `main`:
- Требовать Pull Request и запретить прямой push / force-push / deletion.
- Запретить bypass, включая администратора, если план GitHub поддерживает этот вариант.
- Зафиксировать обязательные checks после проверки имён и триггеров. У существующего `Quality` есть `paths-ignore` для `docs/**` и `**/*.md`: **не делайте его обязательным, пока не обеспечите check для каждого PR**, иначе документальные PR могут заблокироваться.
- Человеческое утверждение изменений: настроить минимум один независимый review, когда PR создаётся GitHub App/ботом и доступен отдельный рецензент; иначе использовать обязательный PR + ручной merge владельца.
- Не назначать AI-агентам bypass. Не включать auto-merge.
- Проверить настройки действующего environment `production` отдельно; AI-агенты не должны иметь к нему доступ.

Доступный GitHub connector не имеет полномочий изменять branch protection/rulesets, поэтому правила создаёт владелец в GitHub Settings.

## Подключение провайдеров (следующий этап)
- Claude: установить официальный Claude GitHub App и отдельно настроить минимально разрешённый workflow на `anthropics/claude-code-action`; авторизация через защищённый GitHub Actions secret (например, `ANTHROPIC_API_KEY` или `CLAUDE_CODE_OAUTH_TOKEN` при поддержке).
- Codex: **приоритет — Codex Cloud Code Review через ChatGPT Plus**, без отдельного OpenAI API key. Владелец открывает Codex, подключает GitHub только к `TRAP44/football-analytics-cloudflare`, включает Code review, затем на отдельном PR проверяет `@codex review`; после успешного теста — Automatic reviews. В Plus действуют лимиты Codex, а доступ к Codex Cloud зависит от доступности для аккаунта. 
- Альтернатива `openai/codex-action` с `OPENAI_API_KEY` требует отдельной оплаты API; она не активируется при варианте Plus. Черновик PR #791 — необязательный API-пилот, не предназначенный для объединения в рамках Plus.
- Использовать только проверенные официальные экшены, зафиксированные на commit SHA после аудита, избегать запуска в привилегированном `pull_request_target` на недоверенном коде.
- В целях безопасности держать исходный код PR и любые пользовательские сообщения недоверенными. Не делиться Production-секретами ни с одним AI job.
- Держать выделенные лимиты расходов, защиту от циклических комментариев и разрешённый список запускающих пользователей.

## Порядок внедрения
**Этап 0** — аудит, отдельная ветка и инструкции агентам (этот PR): только документы, никакого включения workflow.
**Этап 1** — владелец включает защиту `main`, проверяет обязательные проверки и разрешения приложений.
**Этап 2** — подключить Codex Cloud к репозиторию под аккаунтом ChatGPT Plus; вручную проверить ревью `@codex review` на безопасном PR, затем включить Automatic reviews, если доступны. Секрет OPENAI_API_KEY не нужен.
**Этап 3** — после настройки Codex Cloud создать отдельный PR для Claude issue-to-draft-PR с минимальными разрешениями и ограничениями расходов, проверить запуск на изолированной задаче.
**Этап 4** — ограниченный оркестратор очереди задач, бюджеты, не более заданного числа циклов, human release gate.

## Красные линии
- Никакого изменения названия, случайной переработки UI и потери русской локализации.
- Никакого изменения существующих PR, в том числе незавершённых исправлений, без отдельного поручения.
- Никакого ручного или AI-triggered production deploy, изменения production SQL, API keys, Telegram bot token или оплат.
- Слияние PR в `main` потенциально запускает production. Его делает только владелец после проверок.

## Критерий готовности автоматизации
Оба AI-провайдера авторизованы с минимальными правами; обязательные проверки проходят или блокируют merge; PR создан ботом как draft; Codex оставляет проверяемый review; Claude исправляет замечания без доступа к Production; владелец один принимает решение о merge; итоговый Production не меняется до этого решения.

## Подписка Plus: сценарий без отдельного OpenAI API
1. Войти в Codex со своим ChatGPT Plus и подключить GitHub-репозиторий MatchRadar (требуется действие владельца при авторизации).
2. В настройках Codex для репозитория включить Code review. Запросить ручную проверку комментарием `@codex review` на безопасном открытом PR.
3. Сверить замечания с diff и тестами. Только затем включить Automatic reviews с запуском при переходе PR из Draft в Ready, если этот режим доступен в UI.
4. Кодовые правила находятся в `AGENTS.md` → `## Code Review Rules`. Для их применения во всех PR документ необходимо провести через разрешённый owner-controlled merge после проверки.
5. Codex code review не является обязательной GitHub status check и не заменяет требование approvals; release gate нужно настроить отдельно.
6. Не предоставлять Codex/Claude Cloudflare API token, Supabase service role key, Telegram bot token, API-Football API key, платёжные секреты или прямой доступ к Production.
