# MatchRadar — безопасный запуск Telegram Stars

Состояние: **подготовка**, приём реальных платежей выключен. Ни один шаг ниже
не должен автоматически менять MONETIZATION_ENABLED на true.

## Реализовано
- FREE / PRO / PREMIUM, лимиты на AI-разборы, покупка и управление подпиской
- Match Pass / Day Pass / Weekend Pass; длительность, область применения и лимиты
- Подписанные payload для счетов; XTR, сумма и идентификатор пользователя проверяются на сервере
- Выдача доступа после Telegram successful_payment, возврат, дедупликация и ручная сверка
- Проверка readiness webhook и запрет pre-checkout при выключенной монетизации
- Панель профиля, которая показывает будущие тарифы, но **не предлагает оплату**, пока флаг выключен

## Перед включением реальных платежей
1. Убедиться, что Telegram bot token и секрет webhook относятся к **основному боту MatchRadar**.
   Проверить реальный `getWebhookInfo`, URL `/telegram/webhook`, события `pre_checkout_query`
   и `message`, а также отсутствие свежих ошибок доставки. Нельзя подтвердить это только CI.
2. Проверить секреты Worker в Cloudflare без вывода значений и отказ API счета при
   MONETIZATION_ENABLED=false (ожидается 404 на маршруте).
3. Проверить Supabase: RLS включён у `billing_payments`, `user_entitlements` и `users`;
   только доверенный сервер имеет доступ к записи; необходимые RPC Pass существуют.
4. Проверить тарифы и цены с владельцем проекта. Значения по умолчанию: PRO 199 Stars
   и PREMIUM 399 Stars за 30 дней; Match Pass 39, Day Pass 89, Weekend Pass 149 Stars.
   Продолжительность подписки, допустимость автопродления и содержание платного доступа
   должны соответствовать фактически работающим функциям.
5. Провести **контролируемую покупку** Telegram Stars самим владельцем только после
   явного согласия на реальное списание. Не отправлять и не создавать настоящие счета
   автоматически при аудите. Проверить: успешное списание, план в профиле,
   дневную квоту, повтор webhook, отмену подписки и возврат с отзывом доступа.
6. Проверить ссылку на поддержку платежей и правила возвратов в Telegram и Mini App.
7. Только после успешного smoke-теста, с подтверждением владельца, выставить
   `MONETIZATION_ENABLED=true` в `wrangler.jsonc`, выполнить Quality/CodeQL,
   release gate и production deploy. Иметь rollback-план.

## Критерии готовности
Провести проверки для FREE (нет оплаты), PRO и PREMIUM (корректные сроки и лимиты),
каждого Pass (scope/expiry/usage), повторного успешного события,
старого/refunded charge и отказа webhook. Никаких начислений по сигналу
от браузера без проверенного server-side `successful_payment`.

**Важно:** автоматические тесты не доказывают работу реального платежа; до проверки
реального Telegram не обещать покупателям доступ к платным функциям.
