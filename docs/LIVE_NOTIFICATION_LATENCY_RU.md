# Быстрые уведомления LIVE

Обычный Cloudflare dispatch и полный Background Jobs остаются раз в 5 минут. На Workers Free выполнение задач не переносится: лимит CPU cron прежний. Уже запущенный GitHub runner после полного прохода использует оставшуюся часть пятиминутного окна для минутных LIVE ticks (не больше четырёх). Дополнительные workflows и секреты не нужны.

Каждый tick — только голы/карточки активных матчей с подтверждёнными свежими часами, до двух fixtures. Не выполняются AI-разбор, составы, итог дня, предматчевые расчёты и рассылка «сегодня играет». Та же runtime-пауза и глобальная распределённая блокировка `cron-global`, отдельный minute job key. Не запущенная из GitHub scheduled-ветка быстрый профиль не получает. Матчи и люди обходятся отдельными LIVE курсорами; будущие матчи не занимают их страницы.

Начало новой работы ограничено мягким бюджетом20с; уже начатый запрос завершается по своему deadline. Отложенный fixture не сдвигает recipient cursor. Обычный полный проход остаётся резервным путём, а нехватка времени/квоты не отменяет его. Короткие сообщения также больше не ждут завершения составов, кривой AI и табло.

Каждая дополнительная реальная отправка запроса к API-Football, включая retry, использует существующий `prematchProviderClaim` перед network send. Tick и предматчевый фон делят атомарный дневной budget `prematch-provider-requests`:25% от подтверждённого лимита, максимум1875 при PRO7500. Остановка при remaining≤50% (учитывается весь наблюдаемый расход, консервативно). Чтение/claim недоступны — отказ, не обход. `/status` для восстановления подтверждённой квоты не считается платным data request. Прежние Supabase relay, общий minute guard, provider cooldown и Telegram delivery ledger/unknown/429 сохраняются.

Выключатель без деплоя: GitHub repository variable `LIVE_NOTIFICATIONS_FAST_ENABLED=false`. Пусто — быстрые ticks включены. Общие выключатели уведомлений продолжают действовать.

Это целевая частота проверки внутри работающего runner, не обещание доставки за60с: GitHub может задержать старт, полная задача/доставка могут занять время, а API/Telegram — ограничить запросы. Источник должен сначала показать событие. Реальную доставку подтверждают отдельные операционные наблюдения, не тесты cadence или HTTP200.

Read-only Observe Live Usage теперь отдельно показывает агрегаты коротких уведомлений и количество pending старше24ч/старейшую дату. Не читает пользовательские ID, не меняет результаты; pending может означать перенос матча, а не ошибочный итог. Пустая выборка AI не доказывает ни мгновенную работу, ни неисправность.
